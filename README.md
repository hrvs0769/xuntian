# 巡天 · 太阳系

一个可以亲手拨动时间的太阳系。

打开就是地球的晨昏线，城市灯光沿着海岸线亮着。十秒后镜头退出大气层，
整个太阳系铺开在眼前——八条轨道、一颗恒星、一层极淡的黄道尘埃。
你可以拖着转、滚着缩放、点任意一颗星球落下去看；
也可以把时间从「一秒等于一天」拨到「一秒等于一年」，看行星在轨道上跑。

所有位置都是真的。不是示意图。

## 运行

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 产物在 dist/
```

无后端、无接口、无追踪。构建产物是纯静态文件。

## 它为什么看起来是那样

这个项目的核心矛盾是：**真实比例和可看的画面是互斥的。**

地球半径 6371 km，日地距离 1.496 亿 km。按真实比例，在能把海王星
（30 AU）装进画面的距离上，地球只有 0.0004 个天文单位——不到半个像素。
任何"真实比例太阳系"的截图，行星都是一堆看不见的点。

处理办法不是简单放大，而是**给每个天体一个"最小屏幕半径"**：

```js
// src/scene/system.js
const MIN_PX = { sun: 7.0, planet: 3.0, moon: 1.6 };
const vis = Math.max(b.radius, MIN_PX.planet * worldPerPixel);
b.group.scale.setScalar(vis / b.radius);
```

近看时这条规则完全不起作用，画面是精确的真实比例；
远看时它悄悄介入，把天体托到"刚好能看见"。用户永远不会发现这条规则，
但没有它，"整个太阳系"这一镜根本不成立。

同一条思路贯穿全片：

| 场景 | 真实情况 | 处理 |
| --- | --- | --- |
| 太阳日面 | 中心亮度是边缘的 2.5 倍 | ACES 会把 1.0 以上压成一片白，所以日面整体压到线性 1.1，把细节留在 0.3–1.4 这段窄区间里 |
| 土星环 | 2026 年太阳在环面下方 23.7° | 环影会把整个北极冠盖住，北半球糊成一张等高线图。机位改为相对环面定位，从受光侧低仰角看过去 |
| 月球 | 没有大气，晨昏线是刀切的 | 法线浮雕在晨昏线和轮廓处淡出，否则屏幕导数退化会在黑暗里点出一片毛刺 |
| 远景行星 | 亚像素 | 最小屏幕半径 + 太阳远距时补一层柔和外晕 |
| 银河 | 逐帧着色要吃掉 40% 帧时间 | 启动时一次性烘焙成 2048×1024 的 HDR 等距柱状贴图 |

  scene/

## 几个值得说的细节

**太阳的米粒组织**用的是"亮细胞 + 暗壁"，不是噪声叠加。
噪声的 0.5 等值线天然连成一张网，把等值线附近压暗，剩下的就是一颗颗米粒：

```glsl
// 两层等值线取并集。只用一层会得到规整的"鱼鳞"——
// 等值线全是同一尺度的闭合环；两层并集之后网络被切碎，才像真实的米粒间隙。
float wall = min(abs(n2 - 0.5), abs(n3 - 0.5) * 1.45);
float cell = smoothstep(0.0, 0.150, wall * 2.0);
float gran = mix(0.56, 1.12, cell);
```

日面峰值要压在泛光阈值（0.95）附近而不是远高于它。一旦整个圆面都在泛光，
米粒组织会被辉光糊平，太阳就成了一块奶白圆片。

**日冕的角向噪声必须建在单位圆上**（`vec2(cos(ang), sin(ang))`）。
直接用 `ang` 会在 `atan` 的 ±π 断点处沿 −x 方向撕出一条假的亮射线。

**深度缓冲不用对数模式。** 自定义着色器不写 `gl_FragDepth`，和内置材质混用
会让所有深度测试失去意义（星空会画在行星上面）。改成收紧近平面
（`near = 0.05d`，正好落在被观测天体之外），所有材质走同一套标准深度。

**土星环的径向剖面贴图同时供两处使用**：环本身，以及行星表面的环影采样。
所以卡西尼缝会在土星云顶上留下一条透光的亮线。环影采样时用 mip bias 取粗一级的
剖面——细密环纹原样投到行星上，整个盘面会变成一张等高线图。

**环纹必须多尺度。** 上一版用逐 texel 的白噪声做细纹，一条细纹都看不见：
环在屏幕上占 ~500 px、贴图 2048 texel，一个像素覆盖 4 个 texel，
mipmap 一平均，白噪声就归零了——环于是变成一块光板。
现在改成 5 个波长叠加（最粗一档只跨 1/5 个环宽），缩到屏幕上仍有明暗。

**临边昏暗是"圆盘"和"球体"之间的分界线。** 一个纯朗伯球在太阳位于相机背后时，
整个圆面亮度是常数——那正是"塑料球"的来源。加一项 `0.22 + 0.78·μ^0.55`
几乎不增加成本，却让每颗行星立刻鼓起来。

**土星不能按黄道仰角摆机位。** 环面与黄道成 26.7°，太阳此刻在环面下方 23.7°；
只要相机落在环面之上，看到的就是被环影盖住的极冠。改成相对环面定位后，
环是开的、行星是亮的，同一个场景换了一个气质。

**轨道线按视距衰减。** 平面上的加法线条读起来像一张靶纸——没有前后就没有纵深。
按 `-mv.z` 做一次 smoothstep，远侧暗下去、近侧亮起来，椭圆立刻"绕到太阳后面去"了。

**远景光点。** 真实比例下 60 AU 外的地球不到一个像素。最小屏幕半径把它撑到 3 px，
但那仍然是个黯淡的小球。再补一层只在"小到只剩几个像素"时淡入的加法辉光，
全景里每一颗行星才成为一粒可辨认的星，而不是一串空标签。

**标签的裁切要按标签自己的位置判断。** `.lbl` 在 CSS 里是 `left:0;top:0` +
`translate(-50%,-50%)`；如果第一帧就被判为"画外"而跳过 transform 赋值，
它会永远停在左上角，露出半截英文名。

**太阳的米粒在整日面尺度上本来就看不见。** 真实米粒直径约 1000 km，
太阳直径 1.39×10⁶ km，可见日面上排着约 1400 颗——在 700 px 的日面上每颗半个像素。
把噪声等值线画满整个圆面，得到的不是太阳，是一张大理石纹/等高线地图。
正确做法：中心几乎不可见（只剩一点沸腾感），临边因为视线斜穿、米粒被径向拉长才显形。

**黑子按黑体温度定亮度。** 半影 ~5000K → 光球的 0.55，本影 ~4000K → 0.23。
乘到 0.18 以下就是纯黑，看着像球被戳穿了。

**日冕不是星芒。** `1/(1+x^k)` 永不为零，所有射线又差不多长——那是滤镜的语法。
真实的日冕只有两三条从活动区伸出的宽流束（盔状流），末端张开成盔形，其余方向很快熄灭，
内部还有沿半径拉长的纤维。用三段 `exp` 叠加才能得到这个结构。

**静止画面里的"颤抖"多半是颗粒。** 胶片颗粒每帧重新随机，在月球这种大面积中亮区
上是 ±1 色阶的噪声，人眼会读成"画面在抖"。颗粒只该压暗部色带——
亮部衰减必须用 `pow(1-lum, 1.7)` 而不是线性。

**相机的最近距离要按天体半径算。** 全局 2×10⁻⁵ AU 对木星是"还隔着一个木星"，
对月球却是"贴到脸上"：距月心 1.89 个半径时 4K 贴图被放大三倍，法线贴图开始打架。
2.6 个半径是分辨率与压迫感的平衡点。

**贴图分级不是优化，是必需品。** 3.35 MB 的高清贴图在 github.io 上要 70 秒——
再压体积也没用，因为问题不在压缩率而在带宽。而全景里所有行星加起来不到 100 px，
传 4096 宽的贴图毫无意义。先给 512 宽（197 KB，全部 13 张），
首屏 10 秒内可交互；高清在后台按"用户最可能点开的顺序"补。
开场那段地球近景用的是低清层，但它是月牙构图、暗面占大半，看不出差别。

**等距柱状球在极点会把一整行顶点收敛成一点。** 大气壳和云壳在极点都会被拉出
一圈放射状条纹——地球北极上方那把"粉黄色碎点"就是这么来的。极点附近淡出即可。

## 部署

**线上地址：<https://hrvs0769.github.io/xuntian/>**

构建产物是纯静态文件，`base: './'` 让它能放在任意子路径下。

```bash
npm run build      # → dist/（约 830 KB JS + 3.35 MB 贴图）
```

推送到 `main` 后由 `.github/workflows/deploy.yml` 自动构建并发布到 GitHub Pages
（仓库 **Settings → Pages → Source** 需设为 **GitHub Actions**，只需设一次）。

`dist/` 也可以直接丢到任何静态托管（Netlify / Vercel / 对象存储 / Nginx），
不需要服务端。本地预览：

```bash
npx vite preview
```

### 关于加载速度

`github.io` 对国内单连接限速约 46 KB/s。这条限制决定了首屏策略：

| | 体积 | 说明 |
|---|---|---|
| 首屏 | ~430 KB | 230 KB JS(gzip) + 197 KB 低清贴图 |
| 后台补全 | 3.35 MB | 首屏 1.8 秒后按优先级串行加载 |

首屏只用 `/tex/lo/` 下 512 宽的贴图——全景里每颗行星只有 3~10 px，
512 宽绰绰有余。高清版本在用户看全景的时候悄悄补上；
如果用户先点开了某颗星球，那颗会立刻插队。

实测：冷启动 10.6 秒（桌面）/ 12.6 秒（移动），回访 2~3 秒。
